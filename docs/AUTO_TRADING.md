# Gaijin Market 自动交易与模拟盘

> 版本 `2.22.0`　|　模拟盘支持 `COMMODITY` 普通商品

## 安全边界

- 聊天交易指令只接受拥有者 UID 的私聊；WebUI 由 AstrBot Dashboard 登录保护。
- 新规则始终从模拟盘开始；逐规则确实盘必须完成规则 ID 二次确认，全局实盘总开关也必须开启。
- 纸面订单只进入共享模拟账户，不会调用真实买卖接口，也不会修改真实盘口。
- 实盘和模拟盘共用规则、风险设置和事件模板，但账户与订单存储严格分离。

## 真实市场模型

War Thunder Market 是按 `market_name` 聚合的玩家限价订单簿：

- 买单和卖单都带数量，支持部分成交；普通商品没有传统无价格保护的市价单。
- 买单创建时冻结 GJN，卖单创建时冻结商品；撤销后释放未成交资金或库存。
- 卖单价格不高于现有买盘时可立即成交；买单价格达到卖一价时可吃掉卖盘，剩余数量继续挂单。
- 普通商品订单持续有效，不实现 72 小时自动过期；改价等同于撤单重下。
- 价格步进为 0.01 GJN，单笔数量 1–1000；真实最低/最高价格优先读取 `cln_market_info`。
- 本插件按产品要求固定 15% 卖家手续费，不读取站点动态 `marketFee` 或商品专属 `market_fee`；界面会注明可能偏离部分商品的真实结算。

## 模拟盘架构

- `PaperTradingEngine`：共享模拟账户、订单、FIFO 批次、场景和持久化门面。
- `PaperMatchingEngine`（`core/paper_engine.py`）：纸面订单撮合、资金/库存冻结、成交和 FIFO 成本。
- `PaperModels`（`core/paper_models.py`）：订单、成交、批次、账户、盘口和场景 DTO。
- `AutoTrader`：规则评估与执行路由；纸面规则只调用纸面引擎，实盘规则只调用真实市场适配器。
- 前端 `views/trade/paper-workbench.mjs`：真实盘口、模拟账户、限价票据、订单、成交和场景界面。

## 撮合与账户规则

1. 新订单先与当前可见真实盘口撮合，成交价取外部档位价；剩余数量进入未成交订单。
2. 新盘口版本按价格优先、同价创建时间优先处理纸面挂单；同一 `book_version` 不重复消费。
3. 买单冻结 `剩余数量 × 限价`，成交价更低时返还差额；卖单冻结未成交库存。
4. 卖单按 FIFO 消耗账户最早批次，固定 15% 手续费按单件结算；已实现盈亏 = 税后到账 - FIFO 成本。
5. 自动规则允许部分买入：剩余买单继续开放；每次买入成交后，为已成交数量尝试卖出。规则可以同时拥有买单和卖单。
6. `once` 在目标买入量和卖出量都完成后停用；`loop` 完成后重置周期并继续等待买点。
7. 自动规则受总预算、每日限额、单笔上限和最大数量约束；手工订单只校验可用现金、库存、价格区间和数量。
8. 普通纸面订单不自动过期；停止/急停/删除规则只处理本插件跟踪的纸面订单。

## 场景盘口

- 工作台删除手工编辑档位，并提供“生成行情场景”和“结束场景”操作。
- 场景延迟默认 5 秒，可配置 1–60 秒；持续默认 30 秒，可配置 5–600 秒。
- 场景按当前规则的买卖缺口选择一个目标侧，逐步增加合成流动性；完成该侧后再切换另一侧，并始终保证买一低于卖一。
- 场景只对当前规则可见；自动规则和手工限价单均可参与，场景内成交使用临时的规则账户快照，期间锁定当前商品。
- 场景结束时只回滚当前规则的场景订单、成交、现金、FIFO 批次和状态，其他规则并发产生的交易保留。

## 数据与升级

模拟账户状态保存在 `paper_state.json`；旧版本的 `trade_rules.json`、`trade_runtime.json`、
`trade_paper_books.json`、交易事件和 `logs/trade-*.jsonl` 会在首次升级到 2.22.0 时清理一次。
账户登录、订阅、输出模板、交易风险设置和全局环境开关保留。

## API

- `GET trade/paper/overview`
- `GET trade/paper/book?market_name=...`
- `GET trade/paper/markets/search?query=...`
- `POST trade/paper/orders`
- `POST trade/paper/orders/<order_id>/cancel`
- `POST trade/paper/scenarios`
- `DELETE trade/paper/scenarios/<scenario_id>`（WebUI Bridge 兼容 POST）
- `POST trade/paper/reset`

## 测试重点

- 盘口深度消耗、部分成交、重复版本不重复成交、可见深度耗尽后不虚拟补足。
- 买单/卖单冻结与撤单释放、15% 按件取整、FIFO 成本和盈亏。
- 自动规则部分买入后立即卖出、买卖并行、`once`/`loop` 完成条件和风险额度。
- 场景延迟、规则隔离、自动/手工撮合、定时结束和只回滚当前规则。
- 重启恢复、旧交易数据清理、API 幂等、浏览器 Mock Bridge 验收。
