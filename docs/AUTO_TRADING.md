# Gaijin Market 自动交易

> 版本 `2.21.0`　|　仅支持 `COMMODITY` 普通商品

## 安全边界

- 聊天中的交易指令只接受与 插件控制台账户页配置的拥有者 UID 匹配的 `FriendMessage` 私聊。
- 未配置拥有者 UID 时自动交易直接禁用，不回退 AstrBot 管理员判定。
- WebUI 交易页由 AstrBot Dashboard 登录保护，所有 Dashboard 管理员均可操作。
- 新规则始终从模拟运行开始；逐规则切换实盘必须二次确认规则 ID，且全局实盘总开关必须已开启。
- 全局交易环境开关会批量尝试当前规则；有持仓、挂单或额度不满足的规则会被跳过并报告原因。
- 全局实盘关闭后禁止新的实盘买入和逐规则切换实盘，但已有实盘持仓仍可撤单、挂售和清仓。
- 模拟规则可执行隔离的“完整模拟演练”：只读取一次真实盘口，后续成交由模拟深度补足，不修改规则持仓或累计收益。
- 模拟工作台可为单个模拟规则持久保存替代盘口；保存后所有自动检查只使用该盘口，不调用真实买卖接口。
- 实盘要求总开关开启，且总预算、每日限额、单笔上限、最大数量均大于 0。
- 交易事件只发送到拥有者私聊；没有私聊会话时只写事件日志。

## 固定费率

手续费按产品要求固定为 **15%**，不读取站点 `marketFee`。

```text
税后到手 = floor_to_0.01(税前价格 × 0.85)
税前价格 = 能令税后到手 >= 目标值的最低 0.01 GJN 价格
```

## 执行规则

1. 最低卖价达到买入限价后读取完整盘口。
2. 只统计买入限价以内的卖单深度；允许部分成交。
3. 买单提交后只撤销能通过订单 ID 或事务 ID 确认属于本插件的未成交余量，并等待撤单生效。
4. 目标税后价以上的求购单覆盖多少就立即卖多少，成本与到账按实际盘口价格记录。
5. 未卖出的部分按达到税后目标所需的税前价发布卖单。
6. `once` 在清仓后停用；`loop` 清仓后重新等待买点。

## 模拟交易工作台

- 新建规则成功后控制台自动打开全屏工作台；其他模拟规则可从规则卡随时进入。
- 工作台左栏展示阶段、持仓、挂售、成本、到账、轮次、错误和暂停/恢复；右栏展示完整买卖深度。
- 盘口支持逐档新增、修改和删除，价格最多两位小数，数量为正整数，单侧最多 100 档；允许买卖价格交叉。
- “载入当前真实盘口”只填充编辑器；“按规则生成可成交盘口”分别使用买入限价和税后目标反推价生成足量档位。
- “保存并执行”会把盘口写入 `trade_paper_books.json`，并在同一异步锁内立即执行一次纸面状态机检查。
- “恢复跟随真实行情”会删除该规则的模拟盘口覆盖。
- 模拟盘口仅作用于 `live=false` 的规则；切换实盘后旧覆盖会被忽略，切回模拟盘时可继续使用。

## 订单与资产对账

- 下单使用 `transactid + reqstamp`，持久化订单同时记录事务 ID。
- 网络结果不确定时先读取开放订单与库存，不盲目重复下单。
- 买入、卖出和对账发现无法确认归属的开放订单时，规则进入错误状态，不撤销也不接管该订单。
- 卖单需要经过多次可见性确认；订单未出现但库存已返还时按撤单处理，而非伪造成交。
- 通过 `GetContexts` / `GetContextContents` 获取 `contextid/assetid`。
- 同名资产若在买入前已存在，会记录基线数量，只跟踪本次新增的差额。
- 手工撤销自动卖单时，通过库存返回判断“撤销”而不是“成交”。

## 价格与状态

- 所有价格以 Gaijin 原始刻度整数保存，`1 GJN = 10000`。
- 用户输入保留两位小数。
- 买入成本按盘口成交深度计算，卖出按订单成交价记录到账；当前持仓、挂单数量、累计税后收益和完成轮数持久化。
- WebUI、聊天指令和自动交易循环共用同一异步锁，状态修改与下单串行执行。
- 插件重启后恢复未完成状态；错误规则不会自动继续下单。

## 数据文件

位于 `data/plugin_data/astrbot_plugin_gaijin_market_watcher/`：

| 文件 | 内容 |
| --- | --- |
| `trade_rules.json` | 规则定义 |
| `trade_settings.json` | 总开关与风险额度 |
| `trade_runtime.json` | 状态机、持仓、资产分配、自动订单 |
| `trade_paper_books.json` | 每个模拟规则的持久买卖盘口覆盖 |
| `trade_ledger.json` | 上海时区每日买入额 |
| `logs/trade-YYYY-MM-DD.jsonl` | 按上海日期追加的交易事件，每条一行，保留 30 天 |

旧版 `trade_events.json` 首次升级时会迁移到按日 JSONL，并保留原文件作为备份。

## WebUI API

- `GET  trade/overview`
- `POST trade/settings`
- `POST trade/rules/save`
- `POST trade/rules/action`
- `POST trade/rules/drill`
- `GET  trade/rules/workbench?rule_id=<ID>`
- `POST trade/rules/workbench`（`load_live`、`generate`、`save_apply`、`follow_live`）
- `POST trade/mode`（`paper` / `live`，实盘需 `LIVE` 确认）
- `POST trade/stop-all`
- `GET  trade/logs?after=<event_id>&limit=<N>`
